# Инженерный клуб — сайт с личным кабинетом

Проект: сайт образовательного курса для школьников 9–14 лет.
Сейчас это статический HTML/CSS/JS прототип (site.html) — кликабельный, 
но ничего не хранит по-настоящему (прогресс — в localStorage, оплата — демо).

Задача: превратить в рабочий сайт с личным кабинетом.

Стек, который используем:
- Backend/БД/авторизация — Supabase - зарегистрировался 
- Видеозвонок в уроке — Jitsi Meet (iframe)
- Оплата — ЮKassa (подключим позже, не сейчас)
- Хостинг фронтенда — GitHub Pages (репозиторий 79112686806-bot/79112686806-bot.github.io → https://79112686806-bot.github.io/, публикация через
  GitHub Actions). Vercel заменён: *.vercel.app в России без VPN не открывается.
- Отправка писем клиентам — через Supabase Auth (письмо с приглашением/установкой пароля при создании аккаунта после оплаты) или Resend из Edge Function, если понадобится более гибкий шаблон письма

Функциональность:
- После оплаты создаётся аккаунт ученика в Supabase, пароль или ссылка для его установки высылается клиенту на почту автоматически
- У создателя (администратора) есть возможность подтверждать пройденную учеником тему — после подтверждения ученику открывается доступ к следующему блоку курса в личном кабинете

Стиль: не переписывать дизайн и тексты без явной просьбы, 
менять только то, что относится к текущей задаче.
Все секретные ключи — только в .env, никогда не писать их в код напрямую.

Структура и сборка:
- index.html — сайт (бывший site.html)
- admin.html — админ-панель (/admin.html), доступ только при profiles.role = 'admin'
- scripts/build.mjs — собирает dist/: копирует страницы и пишет dist/config.js
  с публичными URL и publishable-ключом Supabase (из .env локально, из Secrets репозитория
  в GitHub Actions на проде).
  Service role key в config.js и в браузер не попадает никогда.
- chat.js — общий чат (кабинет и админка); course-page.js — шаблон страницы курса
  (используют и сайт, и сборка).
- SEO: у публичных разделов свои адреса (/, /programmy/, /kak-prohodyat-zanyatiya/,
  /kursy/<slug>/). Сборка создаёт для них готовые HTML-страницы со своими title,
  description, H1–H3 и Schema.org, плюс robots.txt; при заданном SITE_URL — sitemap.xml
  и канонические ссылки. Ссылки навигации — настоящие <a href>, с onclick="return go(...)".
- home-blocks.js — карточки видео (Rutube/VK, плеер грузится по нажатию) и отзывов на главной.
- Документы (оферта, соглашение, политика и согласие на ПДн, оплата и возврат, контакты):
  тексты в docs/*.html с подстановками {{inn}} и т.п., данные продавца (самозанятый, НПД) — в site-info.json.
  Сборка делает страницы /dokumenty/<…>/ и /kontakty/; документы закрыты от индексации.
  Тексты документов — шаблоны, перед запуском их должен проверить юрист.
- Формат курса смешанный: самостоятельные этапы (видео, материалы, задания, чат)
  + встречи с преподавателем на ключевых этапах — тексты сайта должны это отражать.
- Оплата курса — три варианта: пробное занятие (первая тема, один раз), блоки (модули) и
  отдельные темы, весь курс (минус уже оплаченное). Цены — в courses.price*, сумму считает
  только сервер (quote_order). Доступ: enrollments.scope full/partial + lesson_access;
  купленные темы открываются по порядку после подтверждения преподавателем.
- Игра «Мемо «Инженерия»: исходники (PNG карточек, документ с историями, развёртка коробки) — в папке
  «Карточки МЕМО/» (в git не попадает). `npm run memo:import` → content/memo.json (тексты из .docx),
  `npm run memo:images` → assets/memo/*.webp, `npm run memo:qr` → «Коробка с QR.png» и QR/ (2 кода на /igra/,
  1 на /igra/ideya/). Шаблон страниц — memo.html, логика — memo.js; сборка делает /igra/, /igra/<slug>/,
  /igra/ideya/. Идеи детей — таблица memo_ideas, видео к карточкам — memo_videos (вкладка «Игра» в админке).
  Ролики — отдельный проект video/ (Remotion): `npm run prepare-cards`, `npm run render` → video/out/*.mp4.
- Исследования: шаблон таблиц темы — lessons.research_plan (jsonb), данные ученика — research_answers.data;
  research.js рисует таблицы (ввод в кабинете, просмотр в админке), среднее считает сам. На сайте —
  только названия и таблицы, без объяснений (объяснения — на занятиях). Методички — content/issledovaniya-*.md.
- Интерактивные мультфильмы («серии»): плеер — episode.js (граф вопросов, голос/кнопки), в занятии — карточка-перевёртыш
  (спереди серия, на обороте встреча с преподавателем). Ролики — закрытый бакет episodes (`node scripts/upload-episode.mjs ep1 <папка>`),
  к занятию подключаются через lesson_content.video_url = 'episode:ep1'. Ответы детей — таблица episode_answers
  (админка → «Ответы в сериях»). В плеере — управление как в обычном видеоплеере (панель поверх кадра, полоса перемотки по просмотренному, ±10 с, громкость,
  полный экран, клавиши, двойное касание; при повторе ответы не спрашиваются заново; место просмотра — в localStorage, «Продолжить»), реакции на ответы
  (узлы p* по словам в «проблеме»), обращение по имени (<серия>/names/<имя>-hi|bye.mp3 поверх ролика; тайминги dur/voice(at, room — если имя длиннее, кадр ждёт)/pickAt
  в episode.js берутся из video/out/ep1/player/timing.json). Обложка (карточка в кабинете и фон экрана «Начать») — assets/episodes/<серия>-cover.webp
  (`node ep1/cover.mjs` в video/). Производство роликов — video/ (Remotion + three.js 3D, озвучка Qwen3-TTS), в git не попадает.
- Админка: меню слева по группам (Работа с учениками / Курсы / Сайт), на главной — плитки «что нужно сделать».
- Клиент Supabase в странице — глобальная переменная `sb`, создаётся через `makeSupabase()` из sb-client.js
  (своя очередь вместо navigator.locks, запасное хранилище, таймауты запросов, плашка «нет связи»).
  Библиотека supabase-js лежит в vendor/ (не с CDN); сборка ставит метки ?v=<хэш> у своих скриптов.
- Локально: `npm run dev` → http://localhost:3000.
- Публикация: push в main → .github/workflows/pages.yml собирает dist/ и выкладывает
  на GitHub Pages. Сайт рассчитан на корень домена (абсолютные пути /...), поэтому
  нужен свой домен (или репозиторий <user>.github.io), а не адрес вида /Sait/.
